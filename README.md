# 台股財報評分

每個交易日收盤後，自動從證交所與櫃買中心開放資料抓取全市場（上市＋上櫃）財報，依規則評分並給出買進／觀望／賣出標籤，在手機網頁上檢視。

- **全市場**：可搜尋、依標籤／產業篩選、依評分／市值／營收年增／本益比排序
- **產業前三名**：證交所產業分類，可切換「依評分」或「依市值」
- **熱門產品**：每檔標出主力產品，依產品題材分組；每天依成分股「近 5 日平均成交值」排出最熱門的 20 個題材
- **主題族群**：依主力產品／題材分組（散熱、AI 伺服器、記憶體…），族群內全部成分股依評分或市值排名

## 部署（沿用你原本選股工具的做法）

1. 建立新的 GitHub repo（可設為私有），把本資料夾內容全部上傳
2. Actions 頁籤 → 「更新財報評分」→ **Run workflow** 可隨時手動更新
3. Settings → Pages → Source 選 `main` 分支、資料夾 `/docs`，網址就是手機要開的頁面
   （私有 repo 使用 Pages 需要付費方案；若是免費帳號，repo 需設為公開）

之後週一至週五台灣時間 17:41、21:41 自動更新（17:41 對齊央行收盤匯率與法人資料公布；21:41 補上約 21:00 公布的融資融券）。

## 月營收與「營收連兩月成長」

- 評分納入單月營收月增率、單月營收年增率（與累計年增率並列）
- 最近兩個月（含）以上單月營收「月增 > 0 且 年增 > 0」列為重點：評分加分、卡片顯示「營收連N月↑」，全市場可用「★ 營收連兩月成長」篩選
- 最新月份來自開放資料；上一個月從公開資訊觀測站月營收彙總表補抓，之後每月自動累積在 `data/revenue_history.json`
- 門檻與加分在 `config/scoring.json` 的 `revenue_streak`
- 月增率受工作天數與農曆年影響較大，一、二月的結果要特別留意

## 資金流向

「資金流向」分頁與股票卡片的籌碼明細：
- 三大法人（外資、投信、自營商）個股買賣超：當日、近 5 日、連續買賣天數，金額以最新收盤價估算
- 融資融券：融資餘額與近 5 日變化、融券餘額、券資比
- 排行：產業、熱門題材的法人 5 日淨買超金額；個股清單（法人買／賣超、外資或投信連買、籌碼集中、法人買融資減、法人賣融資增、基本面佳＋法人買、成長潛力＋法人買）
- 資料：上市來自證交所 T86、MI_MARGN；上櫃來自櫃買中心。每筆資料都要通過核對才採用：外資＋投信＋自營商＝三大法人合計；融資今日餘額−前日餘額＝買進−賣出−現金償還。無法核對的來源不採用
- 訊號門檻在 `config/scoring.json` 的 `flows`；資金流向不影響評分
- 診斷：`data/flow_diag.json`

## 匯立分點（讀取 huili）

分點資料維持在 huili repo 抓取，本網頁開啟時直接讀 `https://markwu27928.github.io/huili/data.json`（同網域，不需排程）：
- 股票卡片：「匯立買／匯立賣」標記，明細顯示最新一天買賣超、連續上榜天數、近 5 日累計
- 資金流向分頁：匯立分點買超、賣超（最新）、5 日累計買超、匯立買＋法人買、匯立買＋基本面佳
- huili 每天只收錄買超、賣超各前 50 名，未上榜不代表沒有交易
- 讀取端會檢查資料格式版本（目前 1）；huili 改格式時要一併提高版本。讀不到或版本不符時只顯示說明，不影響其他功能

## 營收成長潛力股

全市場分頁的「🚀 營收成長潛力」篩選，以下條件全部符合才列入（門檻在 `config/scoring.json` 的 `growth_potential`）：
- 近 3 個月營收合計年增 ≥ 25%（以合計計算，單月暴衝不會被放大）
- 比前 3 個月加速 10 個百分點以上
- 近 3 個月每個月年增皆為正
- 最新月營收創近 12 個月新高
- 單月營收 ≥ 1 億元（排除基期過小）、本業未虧損
- 建材營造業不適用（交屋時一次認列營收，月營收年增失真）

這是篩選參考，不影響評分與買賣標籤。營收歷史自動從公開資訊觀測站回補近 13 個月。

## 匯率與外資（網頁標題）

網頁最上方顯示美元兌台幣、外資買賣超，並判讀「偏匯入／偏匯出」。每個交易日隨排程更新，資料存在 `docs/macro.json`。
- 外資買賣超：證交所三大法人買賣金額統計（外資及陸資＋外資自營商，上市市場），單位億元
- 匯率：中央銀行公布的新臺幣/美元銀行間收盤匯率（每營業日 16:00–17:00 公布一次）；央行資料抓取異常時改用國際參考價，網頁會標示「非官方」
- 判讀規則：近 5 日外資累計買賣超超過門檻、新台幣近一週升貶超過門檻，兩個訊號相加；門檻在 `config/macro.json`
- 這是資金流向參考指標，不是外資實際匯出入金額（官方統計為每月公布）
- 這一步失敗不影響股票資料，網頁會顯示「暫缺」

## 調整主題族群

編輯 `config/themes.json`：族群名稱對應股票代號清單，可新增族群、增刪股票，一檔股票可屬於多個族群。
找不到的代號會顯示在網頁族群標題下方，以及 Actions 執行紀錄中。族群名單是人工整理的題材分類，不是官方資料。

## 調整熱門產品題材

編輯 `config/products.json`：每個題材底下是「股票代號：主力產品」。`show_top` 是顯示幾個題材（預設 20），`heat_days` 是熱度採計天數（預設 5）。
熱度用成交值計算，第一週資料天數不足 5 天時，以已有的天數平均。主力產品為人工整理，非官方資料。

## 調整評分規則

全部在 `config/scoring.json`：

- 每個指標 `bad` 得 0 分、`good` 得 100 分，中間線性內插；`bad` 大於 `good` 代表越低越好
- `weight` 是權重；缺資料的指標會自動略過並重新配分
- `buy_above` / `sell_below`：買進與賣出的分數門檻
- `buy_min_coverage`：資料涵蓋度低於此值時，最高只給「觀望」
- 有「本期虧損」「本業虧損」「負債比過高」等風險旗標時，不會給買進

改完推上去，下一次排程（或手動 Run workflow）就會套用。

## 資料正確性保護

- 每次執行都產生 `data/diagnostics.json`：各來源筆數、實際欄位名稱、每個欄位的填值比例、無財報公司清單
- 營收、淨利、EPS、資產、權益、股價、資本額等關鍵欄位填值比例低於門檻，或公司代號對不上，就判定失敗、不覆蓋舊資料，Actions 會顯示紅燈
- 財報涵蓋六種格式：一般業、異業、銀行、證券期貨、金控、保險
- 市值以「已發行股數 × 收盤價」計算（不假設面額 10 元）
- 排除 ETF（0 開頭）與存託憑證（91 開頭）
- 官方資料暫缺某公司財報時，沿用上一次抓到的財報並標示「沿用前次財報」；從未取得財報的公司標「資料不足」，不單靠估值給買賣標籤

## 已知限制

- 官方開放資料在財報截止日後數天內可能不完整（例如金控財報晚於一般公司上線），每天重跑會自動補齊
- 證交所開放資料的股價有時比櫃買中心晚一天，卡片內會顯示股價日期
- ROE 以累計淨利依季別年化估算，不是精確的 TTM 數字
- 營收年增使用月營收資料的「累計營收年增率」
- 金融業不評毛利率、營益率、負債比、流動比，改以 ROE、營收成長與估值評分
- 這是規則評分，不是股價預測，不構成投資建議
